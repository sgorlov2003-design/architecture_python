# Домашнее задание 01: Документирование архитектуры в Structurizr

---

## Описание системы

Система **«Фитнес-трекер»** предназначена для учёта тренировок и упражнений: регистрация пользователей, ведение справочника упражнений, создание тренировок, добавление упражнений в тренировку, просмотр истории и статистики за период. Эталон: [MyFitnessPal](https://www.myfitnesspal.com/).

---

## Функциональные требования

| № | Описание |
|---|----------|
| 1 | Создание нового пользователя |
| 2 | Поиск пользователя по логину |
| 3 | Поиск пользователя по маске имя и фамилия |
| 4 | Создание упражнения |
| 5 | Получение списка упражнений |
| 6 | Создание тренировки |
| 7 | Добавление упражнения в тренировку |
| 8 | Получение истории тренировок пользователя |
| 9 | Получение статистики тренировок за период |

---

| Роль | Описание |

## Бизнес-кейс (Dynamic Diagram)

**Описание сценария:** Пользователь создаёт новую тренировку и добавляет в неё упражнения из справочника.

| Шаг | От | Кому | Описание | Протокол |
|-----|-----|------|----------|----------|
| 1 | Пользователь | Fitness Web Portal | Открыть раздел «Новая тренировка» | HTTPS:443 |
| 2 | Fitness Web Portal | API Gateway | REST-запрос | HTTPS:443 |
| 3 | API Gateway | Workout Service | Маршрутизация (создание тренировки) | HTTPS:443 |
| 4 | Workout Service | User Service | Проверка пользователя | HTTPS:443 |
| 5 | Workout Service | Workout Database | Сохранить тренировку | JDBC:5432 |
| 6 | API Gateway | Exercise Service | Список упражнений | HTTPS:443 |
| 7 | Exercise Service | Exercise Database | Чтение справочника | JDBC:5432 |
| 8 | API Gateway | Workout Service | Обновить тренировку (добавить упражнения) | HTTPS:443 |
| 9 | Workout Service | Workout Database | Сохранить связи тренировка–упражнения | JDBC:5432 |

---

## Архитектурные решения (ADR)

**Документирование обоснования архитектуры:**

| ADR | Название | Статус |
|-----|----------|--------|
| 001 | Выбор REST API для доменных сервисов (пользователи, упражнения, тренировки) | Accepted |
| 002 | Выбор PostgreSQL для хранения сущностей предметной области | Accepted |
| 003 | Разделение по объектам предметной области (Пользователь, Упражнение, Тренировка) | Accepted |
| 004 | API Gateway как единая точка входа (по аналогии с эталонной архитектурой курса) | Accepted |
| 005 | Redis для кэширования справочника упражнений и статистики | Accepted |

**Шаблон ADR:**

- Контекст
- Рассматриваемые варианты
- Решение
- Последствия (позитивные/негативные)
